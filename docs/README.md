# docs

Hardware designs, the chip vector listing, and the specs and plans that drive development.

## Where things go

| Path | Purpose | Rules |
|---|---|---|
| [stage1/](stage1/) | Current hardware: Arduino Nano + 2 × MCP23S17. Schematic sheets and wiring tables. | Generated. Edit `tools/design.py` and rerun the tools. |
| [old-1284p/](old-1284p/) | Earlier ATmega1284P design | Frozen. Reference only. |
| [superpowers/](superpowers/) | Specs and implementation plans, one per increment | Follow the templates in its subfolders |
| [chips.txt](chips.txt) | Every test vector in the chip database, with pin names | Generated by `tools/chips.py`. Never edit by hand. |

## Rules for this tree

- Every folder under `docs/` has a README giving its purpose, file format or template, change rules, and
  an index. Read it before adding files; update it in the same commit.
- A new hardware stage gets its own folder (`stage2/` …), generated from a `tools/` script the same
  way `stage1/` is. When a stage is superseded, rename it `old-<name>/` and mark it frozen.
- Images: check in both `.svg` (source of truth, diffable) and `.png` (for quick viewing).
